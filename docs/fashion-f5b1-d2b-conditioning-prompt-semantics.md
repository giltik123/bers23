# Fashion F5b.1 D2b — Kandinsky conditioning prompt semantics

Status: **RESEARCH CONTRACT ONLY**. This step does not generate conditioning tensors, admit Kandinsky runtime execution, change production model catalogs, or enable Try-On.

## Why D2b exists

D2a pinned the immutable conditioning bundle schema but intentionally did not define prompt text. D2b fixes the A/B/C semantic experiment before expensive offline prior generation so D2c can attribute quality differences to one controlled variable at a time.

A shared candidate identity registry is now the single bridge between D2a and D2b. For each candidate it pins the exact prompt-contract SHA-256, negative-conditioning mode and positive-embedding source policy. D2a rejects any bundle manifest whose `conditioningContractSha256` does not equal that registry identity.

## Historical semantics being preserved

- `KandinskyV22PriorPipeline.__call__`: when `negative_prompt is None`, returned `negative_image_embeds` come from `get_zero_embed(...)`, i.e. the CLIP image encoder applied to a zero image. This is `HISTORICAL_ZERO_IMAGE`.
- With an explicit negative prompt, the historical prior appends positive and negative prompts into one prior batch and later splits the resulting image embeddings. This is materially different from zero-image conditioning and is `EXPLICIT_NEGATIVE_PRIOR`.
- `KandinskyV22InpaintPipeline.__call__` concatenates `[negative_image_embeds, image_embeds]` before the UNet and applies classifier-free guidance as `uncond + guidanceScale * (text - uncond)`.

## Why C must reuse B positive embeddings

Equal positive prompt strings are not enough to isolate negative conditioning. The historical explicit-negative path changes prior batch shape from one prompt to positive+negative. Pipeline-owned random latent generation and batch execution therefore do not contractually guarantee that C's positive `image_embeds` are byte-identical to B's single-prompt run.

D2c must either load B's already-built positive tensor into C's bundle or prove byte identity and then use the B tensor as the canonical source. This makes B→C a true negative-conditioning comparison.

## Experimental interpretation

A→B changes positive prompt semantics while retaining historical zero-image negative conditioning.

B→C keeps `image_embeds` byte-identical by source reuse and changes only `negative_image_embeds`: zero-image baseline versus explicit negative prior.

D2b does **not** choose a winner. Selection requires D2c reproducible bundles plus decoder parity/quality review of garment identity, silhouette drift, texture fidelity, seam quality, lighting consistency, latency and memory.
