# BERS — конечный визуальный результат важнее технических метрик

**Дата:** 2026-10-10. **Решение:** P0, выпуск 1.0 отложен. Проверка готового изображения — обязательный отдельный этап. Все алгоритмические тесты и CI-PASS означают лишь вычислительную корректность; они не подтверждают качество готовой фотографии.

## Пересмотр уже показанных пользователю результатов

| Реальная фотография | Предыдущая сильная локальная коррекция | Визуальное решение |
|---|---|---|
| Светлый портрет | Пересвет кожи, потеря деталей лица и одежды, явно неестественная освещённость на белом фоне; новая формула ослабляет пересвет, но эстетически сильно осветлённый портрет по-прежнему хуже исходника | **FAIL**. Для уже нормально экспонированного снимка лучший текущий результат — **не применять улучшение ради самого улучшения** |
| Белая майка | Очевидная яркая овальная область на груди, искусственный локальный свет без учёта реальной геометрии ткани, уничтожение складок при сильном усилении | **FAIL**. Даже мягкая формула с овальной маской остаётся заметной; нужен мягкий ручной выбор области, отсутствие фальшивого края и сохранение фактуры |
| Платье с цветочным принтом | Яркая овальная зона на ткани, осветление выглядит «пятном», узор частично теряет контраст | **FAIL**. Любое изменение должно сохранять читаемость цветов/узора и естественную схему освещения |

Доказательство для этого решения: ранее выгруженные на GitHub исходные фотографии/контакты из PR #987 и локальное A/B в обсуждении PR #995. Отсутствие в новой формуле 255-клиппинга **не снимает ни один FAIL**.

## Новый принцип обработки

1. **Не редактировать, если источник уже хороший.** Пример: светлый студийный портрет. «Профессионально» не значит делать фотографию светлее любой ценой.
2. **Редактировать под конкретный визуальный дефект.** Для тёмного снимка — консервативная коррекция теней с плавным переходом, а не яркое пятно на случайной овальной области.
3. **Никаких подставных масок.** Демонстрационная ellipse-маска позволяет проверить арифметику, но не может считаться настоящим выделением кожи, одежды или переднего плана. В локальной лаборатории — только явная маска, вручную нарисованная мягкой кистью, или определённые по яркости Shadows/Midtones/Highlights.
4. **Подтверждать улучшение целой фотографии.** Сравнить исходник и итог, рассмотреть лицо/кожу, ткань, логотип/рисунок, свет, фон, границы коррекции. Если улучшения нет или виден искусственный эффект — **не принимать**, независимо от баллов PSNR/SSIM/ΔE/клиппинга.
5. **Проверять именно экспортируемый результат.** После визуального выбора передать контролируемому Core Preview → Accept; отдельно сравнить сохранённый FINAL и скачанный PNG. Не судить по размытой миниатюре.

## Результаты нового консервативного A/B (пока не приняты)

На трёх исходных фотографиях проведена отдельная локальная реконструкция мягкой кривой с маской по воспринимаемой яркости: без эллипса, без попытки считать это реальным семантическим выделением.

- **Портрет:** правка не применялась. Намеренно сохранён оригинал — он выглядел естественнее любого показанного ранее осветления.
- **Майка:** только небольшое повышение теней до +0.5 по входной кривой. Видимого овального пятна больше нет; качество чуть аккуратнее, но это **ещё не доказательство профессиональной ретуши**.
- **Платье:** только небольшой подъём теней до +0.25. Цветочный узор и композиция выглядят естественнее, чем в прежнем сильном овальном редактировании; существенность улучшения подлежит человеческому выбору.

Это **эксперимент NumPy/Pillow на тех же настоящих фото**, а не проверка точного TS-релиза BERS; исходный ICC/цвет и вывод браузера могут отличаться. Никогда не переносить вердикт этого ручного A/B на ещё не проверенную hosted CI реализацию.

## Проверка «прошло / не прошло» конечного результата

Четыре независимых визуальных вопроса, которые разработчик/владелец подтверждает по реальному итоговому снимку:

- Освещение, кожа и цвета выглядят естественно?
- Лицо, волосы, ткань и принты остались сохранены?
- Нет ли ореолов, овальных пятен, швов, ломанных масок, плоско наложенной одежды?
- Итог заметно **не хуже**, а для исправляемого дефекта действительно **лучше оригинала**?

**Любой ответ «нет» => REJECT, не публиковать как профессиональный результат.** Отсутствие оценки => REVIEW_PENDING, а не PASS. Тестам запрещено самостоятельно присваивать HUMAN_ACCEPTED. В изолированном dev-Editor обязательный пользовательский чеклист блокирует экспорт неревьюированного PNG; пока нет внешнего независимого приёмщика, это только самопроверка, **не сертификация**.

## Следующие визуальные достижения

- Устранить искусственные границы ручной кистью/тональными диапазонами; затем сравнить фотографию **целиком**, а не усреднённые RGB.
- Добавить сильные реальные тесты на некачественной коже, белой/чёрной ткани, волосах, логотипах, реальном дневном свете и сложных тенях. Снимок хорошего исходного качества служит обязательным *no-op контрольным случаем*.
- Проверить тон/белый баланс совместно, не пересвечивая кожу и не добавляя жёлтую окраску.
- Fashion контролировать отдельно: посадка, ткань, швы, перекрытия руками/волосами — не выдавать безликий альфа-композит за фотореализм.
- Переводить прошедшие человеческую приёмку локальные алгоритмы в отдельные versioned Core v2 tools, сохраняя текущий проверенный v1 контракт/историю и release gate.
